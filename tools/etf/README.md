# Foreign ETFs on TASE (INVESCO + iShares) — refresh tool

Feeds `tase-etfs.html` through the generated file `../../etf_data.js`. Public market data only.

## Refresh (ask Claude to run it)

| Step | What | How | How often |
|---|---|---|---|
| 1 | Prices: year-end closes, latest price, listing date | browser, TASE history page → `tase_history.json` (extractor: `tase_history_extractor.js`) | full range each January; quick mode (from 1 Jan of this year) to refresh the latest price |
| 2 | INVESCO: top-10 + country/sector, fund size | browser, invesco.com/uk pages → `holdings_raw.json`, `aum.json` | monthly |
| 3 | iShares: top-10 + sector/geography, fund size | browser, ishares.com/uk pages → `ishares_raw.json` | monthly |
| 4 | Security numbers, fees, reference index | browser, market.tase.co.il → `tase_funds.json` (INVESCO), `tase_ishares.json` | when a fund is added or a fee changes |
| 5 | Build | `python3 build_data.py` | every time |

Then reload the page, check the numbers, commit and push. `build_data.py` warns about: untranslated
names, price mismatches against the TASE page, adjusted closes appearing in the feed, stale prices,
and every fund-year it withholds for lack of a year-end price.

## Files

* `tase_funds.json`, `holdings_raw.json`, `aum.json` — INVESCO (17 funds, ids = TASE security numbers).
* `ishares_map.json` (security number ↔ price ticker ↔ ishares.com product id), `tase_ishares.json`,
  `ishares_raw.json` — iShares (26 funds, TASE manager 1779). Three funds listed on 2026-11-04 have no
  price ticker yet (`ticker: null`); add it when the price source carries them.
* `fund_text_he.json` — Hebrew names, descriptions, country/sector translations (hand-edited; every
  description claim must match a number in the data).
* `fund_meta.json` — hand-curated: filter category, region (for the portfolio composition), asset class,
  swap flag, and the comparison groups (`exact` = same index, `similar` = different index, same exposure).
* `prices.json` — generated by `update_prices.py`.

## Why steps 2–4 use a browser

TASE (Imperva) and invesco.com refuse scripted requests; we do not work around that. A browser session
reads the pages a person would, and values are copied into the JSON files. Invesco's CSP also blocks
posting from the page to localhost, so extracted text is read from the tool output.

`ishares.com` pages are readable; the extractor can be stored in `sessionStorage` and re-run on each
product page (`eval(sessionStorage.x)`), which keeps each call short. It clicks the exposure tabs
(`#tab-exposureBreakdowns-geography` etc.) because only the sector tab is in the DOM at load.

### TASE page, one fund
`https://market.tase.co.il/he/market_data/security/<SEC>/major_data`, wait ~3 s, then read the text:
`שם קרן מלא`, `דמי ניהול (%)` (the number on the line after the label), `נכס ייחוס`, `מטבע בו נקובות…`,
`שער אחרון (באגורות)` (kept as `last` so the build can verify the price mapping).
A manager's fund list: `market.tase.co.il/he/market_data/f_etf_manager/<id>/about` (INVESCO 2355, BlackRock 1779);
the security links are in the DOM after load.

### iShares page, one fund
`https://www.ishares.com/uk/individual/en/products/<pid>/` — `Net Assets of Fund` table (fund size),
the holdings table (header contains `Weight`), and `[id^="tabpanel-exposureBreakdowns-"]` panels.
For bond funds the holdings table lists issuers (header `Issuer`), not holdings: not used.

### INVESCO page, one fund
`https://www.invesco.com/uk/en/financial-products/etfs/<slug>.html`; scroll to "Holdings" so the charts render.

Rules learned the hard way:
* **Classify INVESCO charts by content, not position.** Swap funds list country first, physical funds sector first.
* **Check the table caption** ("top 10 exposures" vs "Top 10 collateral exposure").
* INVESCO "Economic exposure" is its own look-through figure (a European index can show a few % in the US).

## Price source and return rules

**Source: the TASE history page of each fund** (desktop layout, custom range `pType=8&dFrom=2019-01-01&dTo=<today>`).
`stockanalysis.com` was used first and dropped: it misses trading days, and for many iShares funds it only
starts in Feb 2025 although TASE shows trading since 2019 (the first version of the page was wrong because of
that, e.g. it showed iShares Core S&P 500 as listed 2025-02-05 and INVESCO Nasdaq-100 as listed 2025).
TASE publishes `שער נעילה מתואם` (adjusted close); returns use it, which also handles the 2025 100:1 unit
change of INVESCO S&P 500 (close 258,000 → adjusted 2,569.68 for 2022-12-29). Whether it is also adjusted for
dividends is not established, so the page calls the result a price return.

* Full-year return of year Y = adjusted close at the last TRADED day on/before 31 Dec Y-1 → same for Y (latest
  traded day for the current year). **Both must be within 14 calendar days of the 31 Dec**, otherwise the return is
  withheld ("illiquid"). TASE lists no-trade days with the last price carried, so "the row exists" is not
  evidence of a trade; the extractor treats a row as a trade only if it has a high price.
* No row yet at the start of the year (listing year) → withheld ("listed"), no partial returns are shown.
* Verified: latest prices equal the TASE page for all iShares funds; the iShares S&P 500 / INVESCO S&P 500 returns
  are consistent with S&P 500 USD returns × USD/ILS.
* Nothing here needs `update_prices.py` any more (deleted).

## Sorting

All lists are sorted by fund size (AUM), largest first. EUR-quoted funds are converted at
`EURUSD_FOR_SORT` (1.15) for the ordering only.
